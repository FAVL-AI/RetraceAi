# Candidate patch — separate the prose-credit scan from the structural exemption

**STATUS: PROPOSAL. NOT APPLIED. `FAVL-Engineering-OS` is unmodified and no
machine-wide change has been made.** The shared defect stays **OPEN** until the
patch is reviewed and landed upstream; this repository's compensating control
(`tests/governance/`) is reported separately and does not close it.

## The defect

In `engineering-controls/hooks/pre-commit`, one flag gates two scans:

```sh
if [ "$struct_scan" = "1" ]; then
    ... ATTRIBUTION_STRUCTURAL_PATTERN ...      # broad authorship-LINE scan
    ... AI_CREDIT_PROSE_PATTERN ...             # a credit asserted as prose
fi
```

The approved-evidence class sets `struct_scan=0`, justified in-comment as
skipping *"the broad authorship-LINE scan … the broad one would refuse the prose
too"*. That justification covers the first scan only. The prose-credit scan is
collateral damage, so a sentence asserting a vendor authored the work is accepted
inside any allow-listed `docs/**evidence**/` or `docs/**handoff**/` path.

This contradicts two properties the control states about itself:

- *"Prose credit … scanned in every class that gets the structural pass —
  including allow-listed paths, which is the point."*
- *"`.attribution-allow` is NOT one of those classes. It widens what a file may
  NAME; it never widens what a file may CLAIM."*

Since `is_approved_evidence_path()` requires the path to be listed in
`.attribution-allow`, an evidence path *is* an allow-listed path — and it can
currently make a claim.

## The change

`prose-scan-separation.patch` (37 lines) introduces `prose_scan`, initialised to
`1` alongside `struct_scan`, left at `1` in the evidence branch, and used to gate
the prose grep. The structural exemption the evidence class needs is preserved
exactly; only the claim question is re-enabled.

The patched script passes `bash -n`.

## Before / after — measured, not argued

Run `./reproduce.sh <hook-path> <label>` against each build. Each case is a real
`git init`, a real staged file and a real invocation of the hook.

| Case | Before | After | Intent |
|---|---|---|---|
| **A** prose credit in allow-listed `docs/evidence/` | **ACCEPT** | **REFUSE** | the defect — must flip |
| **B** co-author trailer in `docs/evidence/` | REFUSE | REFUSE | exemption was always narrow |
| **C** legitimate citation in an ordinary path | ACCEPT | ACCEPT | **no new false positive** |
| **D** origin prose (`"Generated by static analysis of …"`) in `docs/evidence/` | ACCEPT | ACCEPT | **the exemption still works** |
| **E** prose credit in an ordinary path | REFUSE | REFUSE | unchanged baseline |

A is the fix. **D is the regression check that matters**: the evidence class
exists so an imported record can describe its own origin in prose, and a patch
that broke D would have traded one defect for a worse one.

## Positive cases — the safeguard must not erase true provenance

`tests/governance/test_real_checker.py` runs eight legitimate-provenance
fixtures against the **real** hook: third-party authorship in a citation, a
bibliography naming people, a copyright line, an SPDX identifier, an Apache
licence grant, a required AI-use disclosure, a dataset attribution requirement,
and prose discussing the attribution policy itself. **All eight are accepted,
before and after.** The proposed acceptance rule holds: *a path exemption may
permit necessary names, quotations and provenance; it must not exempt
unsupported authorship or endorsement claims.*

## Not claimed

- That the upstream defect is fixed. It is not: nothing was installed.
- That this is the only possible fix. It is the smallest one that keeps the
  evidence class's intended exemption intact.
- That the patch is correct for every repository on this machine. It was
  exercised against five cases in throwaway repositories, not against real
  history across every repo the global `core.hooksPath` governs.
- A review. `FAVL-Engineering-OS` has its own history, tests and review process,
  and a control should not be changed by the repository it polices.
