# Attribution control — negative-control record and one defect found

Why this file exists: `.attribution-allow` claims the allowlist "widens what a
path may NAME, never what it may CLAIM". An unverified claim about a guard is
worth nothing, so the claim was tested. Six hostile probes and one benign probe
were staged into an allowlisted path and a real `git commit` was attempted each
time. Fixtures below are written with `<VENDOR>` standing in for a model-vendor
token so this document does not itself depend on the defect it reports.

## Results (real commit attempts, this repository)

| # | Probe staged into `docs/evidence/` | Expected | Observed | Verdict |
|---|---|---|---|---|
| 1 | `Co-Authored-By: ...` trailer | refuse | **BLOCKED** | correct |
| 2 | `Generated-By: ...` trailer | refuse | **BLOCKED** | correct |
| 3 | `Author: Somebody Else` metadata key | refuse | **BLOCKED** | correct |
| 4 | `Contributors: a vendor` metadata key | refuse | **BLOCKED** | correct |
| 5 | `<VENDOR> is a co-author of this document.` | refuse | **ACCEPTED** | **LEAK** |
| 6 | `This includes contributions from <VENDOR>.` | refuse | **ACCEPTED** | **LEAK** |
| 7 | `Recorded environment: CLI 2.1.287, model id ...` (benign fact) | accept | ACCEPTED | correct |

The guard is genuinely discriminating — it is not a rubber stamp; it blocked
four real attribution shapes and it blocked my own `Author:` line in
`PRECHECK.md`, which I then removed rather than exempting. Probe 7 confirms it
does not block the factual toolchain record the precheck is required to carry.

## Defect: prose-credit scan does not run for the evidence class

Localised by running the same two fixtures in three path classes:

| Path class | `struct_scan` | Probe 5/6 result |
|---|---|---|
| `docs/science/_p.md` — no class | 1 | **BLOCKED** (correct) |
| `docs/REQUIREMENTS.md` — plain `allow_names` class | 1 | **BLOCKED** (correct) |
| `docs/evidence/*` — approved-evidence class | **0** | **ACCEPTED** (leak) |

Mechanism, in `FAVL-Engineering-OS/engineering-controls/hooks/pre-commit`:

- line ~376 `is_approved_evidence_path` sets `scan_pattern=$EVIDENCE_FORBIDDEN_PATTERN`
  and `struct_scan=0`, justified in-comment as skipping "the broad
  authorship-LINE scan … the broad one would refuse the prose too";
- line ~437 `if [ "$struct_scan" = "1" ]` gates **two** scans, not one:
  `ATTRIBUTION_STRUCTURAL_PATTERN` **and** `AI_CREDIT_PROSE_PATTERN`.

So one flag disables both, while the justification covers only the first. The
prose scan is collateral damage of a shared flag.

This contradicts two properties the control states about itself:

- line ~101: "Prose credit. Deliberately NOT anchored, and scanned in every
  class that gets the structural pass — **including allow-listed paths, which is
  the point.**"
- line ~435: "`.attribution-allow` is NOT one of those classes. It widens what a
  file may NAME; it never widens what a file may CLAIM."

`is_approved_evidence_path()` requires the path to be listed in
`.attribution-allow`, so an evidence path *is* an allowlisted path — and it can
currently make a claim. The comment at line ~107 records that this exact hole
was found and closed once before for the plain allowlist class; it remains open
for the evidence class.

Scope: any repository on this machine with a `docs/**evidence**/` or
`docs/**handoff**/` path listed in its `.attribution-allow`. The global
`core.hooksPath` means this is every repository, not just this one.

Suggested fix (one line, for Frank's review — **not applied**): give the two
scans independent flags, e.g. set `prose_scan=1` in the evidence branch and gate
the prose grep on `prose_scan` rather than `struct_scan`. The evidence class
then keeps its intended exemption (origin prose such as "Generated by static
analysis of …") while still refusing an assertion that a vendor authored the work.

**I have not modified `FAVL-Engineering-OS`.** It is a separate, public
governance repository with its own history, tests and review, and silently
patching a control to suit the repository it is policing would be precisely the
wrong move. Reported for decision.
